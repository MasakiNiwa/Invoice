# インボイス確認ツール 仕様書

適格請求書(インボイス)の画像・PDFから **適格請求書発行事業者の登録番号(T番号)** を高精度に読み取り、
チェックディジットで検算し、国税庁「適格請求書発行事業者公表サイト」で確認できるリンクを表示するツール。

- 公開: GitHub Pages (`https://masakiniwa.github.io/Invoice/`)
- ライセンス: MIT
- 動作: ブラウザ完結(画像はサーバーに送信しない)。OCRモデルは初回のみCDNから取得しキャッシュ。

## 3. 入力方法

- ドラッグ&ドロップ(ページ全体どこでも)
- ファイル選択(画像: PNG/JPEG/WebP/GIF/BMP、PDF)
- クリップボード貼り付け(Ctrl/⌘+V、スクリーンショット)
- その場で撮影(スマホ: `capture="environment"` でカメラ起動)

## 4. T番号の仕様と検算

- 形式: `T` + 13桁の数字(法人は法人番号、個人事業者等は専用の13桁)
- 先頭1桁がチェックディジット。残り12桁を右から n=1..12 として
  `検査用数字 = 9 − ( Σ Pn × Qn mod 9 )`、`Qn = n奇数→1 / n偶数→2`
- 表示ゆれの許容: `T1234-5678-9012-3`、全角数字、空白区切り、`Ｔ`、`登録番号:` 等

## 5. 読み取りエンジン(多段捜査)

「全体を1回OCRして終わり」ではなく、**T番号が“ありそうな場所”を推定しながら段階的に絞り込む**。

| Stage | 名前 | 内容 |
| --- | --- | --- |
| 0 | PDFテキスト層 | PDFに文字情報があれば直接抽出(最も確実) |
| 1 | 全体レイアウト解析 | 縮小画像を日本語+英語でOCR。単語の位置・大きさを取得し、「T」「登録番号」「適格」等の**アンカー**と文字サイズを推定 |
| 2 | アンカー周辺精査 | アンカーの右側(T番号が並ぶ想定幅 ≒ 文字高×16)を切り出し、文字高が約40pxになるよう拡大、複数の前処理(グレー/二値化/反転)×数字専用OCR(1行モード)で読む |
| 3 | 文字列らしさ検出 | 連結成分解析で「同じ大きさの文字が横に13〜20個並ぶ領域」を検出し、その行を数字専用OCRで読む |
| 4 | タイル走査 | 画像を重なりありのタイルに分割し、ズームレベルを変えながら(粗→細)走査。見落とし対策 |

### OCR エンジン

| | PaddleOCR(既定) | Tesseract |
| --- | --- | --- |
| モデル | PP-OCRv5 mobile 多言語(検出 4.9MB + 認識 16.6MB) | eng / jpn best_int |
| 実行 | ONNX Runtime Web(WebGPU → WASM) | WASM(Worker 並列) |
| 1行読み | 認識器に直接(高さ48pxに正規化) | PSM7 + 数字ホワイトリスト |
| 全体・タイル | DBNet で行検出 → 行ごとに認識(8行ずつバッチ) | PSM3 / PSM11 |

- PaddleOCR は **Web Worker** で実行し(WebGPU も Worker 内で利用)、UI スレッドを止めない。ジョブは Worker 内で1件ずつ処理し、中止されたスキャンの順番待ちジョブは取り消す
- モデルは初回ダウンロード後 **Cache Storage** に保存。アプリを開いた時点で先読みする(データセーバー時は行わない)
- **向きの自動補正**: 文字行の検出枠が縦長ばかりなら横倒しと判断し、90°/270° で読み比べる。横長の行を 0°/180° で読み比べ、信頼度が大きく違えば上下反転

PaddleOCR は日本語の漢字を簡体字で出すことがあるため、記載事項チェックでは頻出字を日本の字体に正規化する。

### 候補の集計

- 読み取りごとに「13桁・T接頭辞の有無・信頼度・ステージ・位置」を記録
- 同じ番号の読み取りを投票で集計、**チェックディジット一致**を最重要視
- 同じ位置の読み取りは桁ごとの多数決で合成(コンセンサス)
- 検算NGの候補は、誤認しやすい数字(3↔8, 1↔7, 5↔6, 0↔8 …)の1桁置換で検算OKになるものを「推定補正」として低スコアで提示
- 早期終了: T付き・検算OK・複数票の候補が得られたら残りを省略(設定で無効化可)

### 可視化(見ていて楽しい)

- 画像上に、現在捜査中の領域(スキャナー演出)、検出したアンカー、文字列らしい領域、候補をオーバーレイ
- 「ルーペ」: いまOCRにかけている前処理済み画像と読み取り結果をリアルタイム表示
- ステージ進捗、捜査ログ(タイムライン)、候補ランキング

## 6. インボイス記載事項チェック(目安)

全体レイアウト解析(または PDF テキスト層)の全文を行単位にまとめ、正規表現で以下を推定する。

| 項目 | 判定 |
| --- | --- |
| 登録番号 | 検算OKの T番号があるか |
| 発行者名 | 株式会社・店 などを含む行 |
| 取引年月日 | 西暦/和暦の日付 |
| 取引内容 | 品名・但し書き・金額行。8% があるのに ※ 等の軽減税率表示が無ければ警告 |
| 税率ごとの合計額・適用税率 | 「10%対象 ¥…」など |
| 税率ごとの消費税額等 | 「消費税」「内税」など + 金額 |
| 宛名 | 御中/様/殿。レシート(簡易インボイス)なら省略可 |
| 税額の検算 | 対象額×税率(内税: r/(100+r)、外税: r/100)と税額が ±1円で一致 |

## 7. 結果表示

- ヘッダー右上: 「公表サイト」(最有力候補が見つかると有効化)・「クリア」
- 候補カード: T番号(4桁区切り表示)・検算結果・信頼度・票数・発見ステージ
- 公表サイトで確認: `https://www.invoice-kohyo.nta.go.jp/regno-search/detail?selRegNo={13桁}`
- 法人番号公表サイト(法人の場合): `https://www.houjin-bangou.nta.go.jp/henkorireki-johoto.html?selHouzinNo={13桁}`
- コピー、画像上の位置へハイライト

## 9. ディレクトリ構成

```
src/
  app/            ルーティング・レイアウト・ナビ
  pages/          画面(Scan / Settings / Help / About)
  components/     UI部品(入力・ビューア・ログ・結果カード)
  lib/
    tnumber.ts    T番号の正規化・抽出・検算・補正(純粋関数, テストあり)
    links.ts      公表サイトURL
    requirements.ts インボイス記載事項チェック(純粋関数, テストあり)
    image.ts      画像読込・前処理(グレー/大津二値化/切り出し拡大)
    pdf.ts        PDF読込(テキスト層・画像化)
    textlines.ts  連結成分による文字列らしさ検出
    ocr/
      engine.ts   OCRエンジン共通インターフェース
      paddle.ts   PaddleOCR(UI スレッド側の窓口、Worker とやり取り)
      paddle.worker.ts  PaddleOCR を動かす Web Worker
      paddle-core.ts    推論本体(DBNet 検出 + CTC 認識、Cache Storage)
      pool.ts     tesseract.js ワーカープール
      pipeline.ts 多段捜査パイプライン(イベント駆動)
      aggregate.ts 候補集計・投票
  store/          設定ストア
```
